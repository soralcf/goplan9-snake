# M0 笔记：工程骨架与 ABI0

状态：已完成（2026-10-19）。本文是 M0 快照；当前进度见 [2.1-CHECKLIST.md](2.1-CHECKLIST.md)。当前实现位于 `internal/arith`；本文的结论按当前代码维护。

## 产出

- `main.go`：唯一入口，调用 `arith.Add(1, 1)` 并打印结果。
- `internal/arith/arith.go`：`Add` 的无函数体声明。
- `internal/arith/arith_arm64.s`：手写 `Add`。
- `internal/arith/arith_test.go`：表驱动测试。

M0 最初把 `add.go` / `add_test.go` / `add_arm64.s` 放在 `main` 包；M1 统一迁到 `internal/arith/`。模块名固定为 `goplan9snake`，不能带 `-`，否则汇编无法引用跨包符号。

## 常用命令

```zsh
go vet ./...
go test ./... -count=1
go build -o snake .
go tool objdump -s 'goplan9snake/internal/arith\.Add' snake
```

`go tool objdump` 读的是可执行文件，不是 `.s` 源码；改完汇编必须重新 `go build` 再反汇编。

## 关键结论

### `TEXT ·Add(SB), NOSPLIT, $0-24`

- `TEXT` 定义函数；`·Add(SB)` 是包级符号，链接后展开为 `goplan9snake/internal/arith.Add`。
- `NOSPLIT` 表示不插入栈分裂检查，来自 `#include "textflag.h"`。
- `$0-24`：`0` 是本地帧大小，`24` 是**参数 + 返回值**的总大小：`a` 8 + `b` 8 + `ret` 8。

### ABI0 与 ABIInternal

- 手写汇编按 ABI0 实现：参数和返回值都在调用者栈帧上，用 `a+0(FP)`、`b+8(FP)`、`ret+16(FP)` 读取和写入。`FP` 是虚拟帧指针，汇编器把它解析成栈偏移。
- Go 声明 `func Add(a, b int64) int64` 使用 ABIInternal（寄存器传参）。编译器生成一个 `<autogenerated>` 的 ABI 包装：把寄存器参数写到栈上，调用 `Add.abi0`，再把栈上的返回值搬回寄存器。
- 汇编函数本身不会被“转成 ABIInternal”；`go tool objdump` 里的 `.abi0` 后缀就是手写实现。
- 当前 `main` 直接调用时包装可能被内联，`go tool nm ./snake` 只看到 `goplan9snake/internal/arith.Add.abi0`。把 `Add` 当函数值使用（`f := Add`）时，包装符号会独立存在。

### `go vet` 检查什么

`go vet` 的 asmdecl 检查把汇编里的 `$帧-参数`、FP 偏移和参数名与 Go 声明逐项对照，可报告：

- `missing Go declaration`
- `wrong argument size`
- `invalid offset`
- `unknown parameter name`

`go build` 不做这些检查；实测把 `$0-24` 写成 `$0-16` 仍能构建，只有 `go vet` 会报 `wrong argument size 16; expected $...-24`。

## 验收证据（2026-10-19）

- `go test ./... -count=1`：11 个子测试全部通过。
- `go vet ./...`、`gofmt -l .`：无输出。
- `go build -o snake .`：成功；`./snake` 输出 `2`。
- `go tool objdump -s 'goplan9snake/internal/arith\.Add' ./snake`：能看到 `goplan9snake/internal/arith.Add.abi0` 和手写的 `MOVD` / `ADD` / `RET`。
- 定向变异：把 `ADD` 改成 `SUB` 后测试正确失败，证明断言有效。

结论：M0 通过。M1 的实现与验收记录见 [4.2-FUNDAMENTALS-NOTES.md](4.2-FUNDAMENTALS-NOTES.md)。
