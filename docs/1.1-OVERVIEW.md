# 实现总览

本文用通俗语言说明自动贪吃蛇的运行流程、核心数据结构与函数职责，不包含实现代码。精确契约见 [2.2-CONTRACTS.md](2.2-CONTRACTS.md)，条目进度见 [2.1-CHECKLIST.md](2.1-CHECKLIST.md)，技术论证见 [3.1-DESIGN.md](3.1-DESIGN.md)，里程碑验收见 [1.2-ROADMAP.md](1.2-ROADMAP.md)。

> 核心心智模型：程序在静态 BSS 中维护一份棋盘状态，每个 tick 选定方向让蛇前进一格，再按固定节奏将整帧画面一次性写到终端。所有函数只做三件事之一：**改状态**、**做决策**、**画画面**。

---

## 一、从启动到退出

```text
启动
  ↓
查询终端行列 (termSize) → 计算棋盘宽高 W × H（H 取偶数）
  ↓
初始化游戏状态 (initGame)：清空棋盘、放长度为 1 的蛇、生成第一颗食物
  ↓
进入备用屏幕并隐藏光标 (termEnter)
  ↓
主循环：
  选下一步方向 (chooseNext)
    ↓
  前进一步 (tick)：普通移动 / 吃到食物 / 填满胜利 / 撞墙或自撞死亡
    ↓
  到达渲染间隔：拼接整帧到缓冲 → 一次写出 (render)
    ↓
  分片睡眠 (sleepUS)
  ↓
填满棋盘（或异常退出）
  ↓
恢复光标和主屏幕 (termRestore) → 打印结果摘要 → 退出进程 (sysExit)
```

两个关键约束：

1. **模拟步进与帧渲染解耦**：后期加速（turbo）时可以走多步才画一帧（跳帧）。
2. **退出前必须恢复终端**：`sysExit` 直接结束进程，不会执行任何 Go `defer`，所有正常和异常退出路径都必须先调用 `termRestore`。

## 二、六个核心数据结构

1. **一维棋盘索引**：棋盘按行展平为一维数组，`编号 = 行 y × 宽 W + 列 x`。上下移动加减 `W`，左右移动加减 `1`（**左右移动必须额外检查是否跨行**，不能只看编号是否在 `[0, N)` 内）。方向编码全局固定为 `0=上, 1=右, 2=下, 3=左`。
2. **占用位图 `occ`（每格 1 字节）**：O(1) 回答“这一格当前是否有蛇”，用于碰撞检测和食物落点检查，但不记录蛇身顺序。
3. **身体环缓冲 `body`（每格 4 字节）**：按从尾到头的顺序保存蛇身格号，维护 `tailSlot` 和 `headSlot` 两个下标（到达 `N` 时绕回 `0`）：
   - 普通移动：尾巴腾出旧槽（`tailSlot` 前进），新头写入下一槽（`headSlot` 前进）。
   - 吃到食物：尾巴不动，新头写入下一槽，长度加 1。
   - **核心不变量**：`occ` 中非零的格子集合，必须始终与 `body` 中 `length` 个有效槽位完全一致且无重复。
4. **食物与伪随机数**：`food` 存格号（`-1` 表示无食物）。生成食物时先用 `Xorshift64` 取随机起点，再沿棋盘线性扫描一圈找第一个空格，避免接近满盘时随机重试退化。
5. **寻路表**：
   - Hamiltonian 环表：`cycleNext[cell]`（环上后继格）与 `cyclePos[cell]`（环上序号 `0..N-1`）。
   - BFS 辅助表：线性队列 `bfsQueue`、首步表 `bfsFirst`、访问代表 `bfsStamp`（每轮 BFS 递增代数 `visitedStamp`，无需每次清零访问表）。
6. **帧缓冲 `frame`**：预先分配的字节画布。每帧在内存中拼好 HUD、边框和棋盘字符，光标归位后一次 `sysWrite` 写出，避免逐格写和清屏闪烁。

## 三、函数职责地图

> 以下为概念名与职责提示；已冻结签名与精确边界见 [2.2-CONTRACTS.md](2.2-CONTRACTS.md)。

### M1：基础工具（已完成）

| 函数 | 职责与实现要点 |
|---|---|
| `CellIndex(x, y, w)` | 二维坐标转一维编号 `y*w + x`（`x` 列、`y` 行，32 位运算）。 |
| `Clamp(v, lo, hi)` | 将 `v` 夹到 `[lo, hi]`；`lo > hi` 时返回 `hi`。 |
| `AbsDiff(a, b)` | 32 位补码回绕的绝对差 `\|a - b\|`；注意 `MinInt32` 取负仍回绕为自身。 |
| `SumTo(n)` | `1..n` 循环累加（`n <= 0` 返回 0）；纯分支/循环练习，不进入游戏路径。 |
| `Xorshift64(state)` | 输入 64 位状态，经 `<<13, >>7, <<17` 移位异或返回下一状态；`0` 是吸收态，种子必须非零。 |
| `FillByte(buf, n, v)` | 将 `[buf, buf+n)` 填为字节 `v`；`n <= 0` 为空操作且不解引用 `buf`。 |
| `Inc()` / `Reset()` | 包级 `NOPTR` BSS 计数器加一 / 清零练习；测试间必须先 `Reset` 且不并行。 |

### M2：终端与系统调用（进行中）

| 函数 | 职责与实现要点 |
|---|---|
| `sysWrite(fd, buf, n)` | 循环写满 `n` 字节，处理短写与 `EINTR`；单次写 0 字节返回 `-EIO`，其他失败返回 `-errno`。 |
| `sysIoctl(fd, req, arg)` | 调用 `SYS_ioctl (54)` 查询终端信息（如 `TIOCGWINSZ`）；失败返回正 errno。 |
| `termSize()` | 对 fd 1 查询窗口行列并打包为 `rows<<32 \| cols`；非 tty 或尺寸为 0 时回退 `24<<32 \| 80`。 |
| `sleepUS(usec)` | 按 5ms 分片循环调用 `libc_usleep`，规避 Go runtime 抢占导致的持续 `EINTR`。 |
| `sysExit(code)` | 直接执行 `SYS_exit (1)` 终止进程；调用前必须已完成 `termRestore`。 |
| `termEnter` / `termRestore` | 进入备用屏幕、隐藏光标、清屏归位；退出时恢复光标与主屏幕。 |

### M3：游戏状态与移动

| 函数 | 职责与实现要点 |
|---|---|
| `initGame(w, h, seed)` | 校验尺寸、清空 `occ`、重置蛇长为 1（头尾同在起点）、修正零种子并生成第一颗食物。 |
| `tickWithDir(dir)` | 按指定方向走一步（唯一移动入口与测试接缝）：越界/自撞判定、吃食物/普通移动、更新 `occ`/`body`/`length`/`ticks`，返回状态码（`Moved`/`Ate`/`Win`/`Dead`）。 |
| `spawnFood()` | 随机起点 + 线性扫描 `N` 格找第一个空格放食物；满盘时设为 `-1`。 |
| `getters` / `forceFood` | 只读查询（长度、头、尾、食物、占用、槽位、状态、tick）与测试专用食物注入。 |

**移动更新顺序（核心易错点）**：
- **普通移动**：必须**先清旧尾，再写新头**。因为新头可能恰好踩进即将让开的旧尾格，顺序反了会把旧尾清成空格或误判自撞。
- **吃到食物**：尾巴不动、长度加 1；若此时 `length == N`，立即返回 `StatusWin`，不再生成食物、不再继续移动。

### M4：渲染与主循环

| 函数 | 职责与实现要点 |
|---|---|
| 棋盘几何计算 | 由终端行列扣减 HUD 与边框，高度向下取偶数，宽度按每格 2 字符折算并夹到 `MaxW`/`MaxH`。 |
| `appendUint` | 将无符号整数格式化为十进制 ASCII 写入缓冲区，供 HUD 显示长度、食物数和 tick。 |
| `render()` | 拼接 `\x1b[H` 归位、HUD、边框与每格 2 字符画布，单次 `sysWrite` 写出。 |
| `run()` | 主循环调度：初始化 → 循环“决策 → 移动 → 按间隔渲染 → 睡眠” → 胜利/异常恢复终端并退出。 |

### M5–M7：自动寻路

| 函数 | 职责与实现要点 |
|---|---|
| 构造 Hamiltonian 环 | 在偶数高网格上预计算闭合环路 `cycleNext` 与 `cyclePos`（第 0 列向下，第 `1..W-1` 列按行蛇形返回 `(1,0) → (0,0)`）。 |
| `chooseNextByCycle()` | 直接返回 `cycleNext[head]`，O(1) 且可证明永不自撞。 |
| `forwardDist(a, b)` | 环上从序号 `a` 到 `b` 的前向步数 `(b - a + N) mod N`，用条件加减实现，无需除法。 |
| 安全窗口判定 | 仅允许环序位于头前方、尾之前的格子：`1 <= forwardDist(hp, c) < forwardDist(hp, tp)`（特判 `length == 1` 与紧贴尾巴 `distToTail == 1`）。 |
| `bfs` | 在安全窗口内的空闲格上搜索从蛇头到食物的最短路径；入队时直接传播“第一步”`bfsFirst`，命中目标即返回 `bfsFirst[food]`，无路返回 `-1`。 |
| `chooseNext()` / `tick()` | 食物在安全窗口内且 BFS 有路时走 BFS 首步，否则退回 `cycleNext[head]`。 |

## 四、为什么“安全窗口 BFS + 环兜底”既快又不会死

把 Hamiltonian 环想象成一条**串起所有格子的单向环形传送带**：

- 蛇身始终占据传送带上从车尾 `tp` 到车头 `hp` 的一段区间；纯沿传送带走永远不会撞到自己，且必能扫过每颗食物，但最坏需 O(N²) 步。
- BFS 捷径只允许在**车头前方、车尾之前**（`1 <= d < distToTail`）的空路上抄近道，绝不跨过车尾，因此抄完近道后蛇身在环上的先后顺序依然合法，永远留有通向车尾的退路。
- 抄近道跳过的身后空格如果刷出新食物，当前安全窗口看不到它，蛇就沿环继续前进；随着车尾不断前移让出空格，该食物终会进入车头前方的安全窗口被吃掉，不会永久饿死。
