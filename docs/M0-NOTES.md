### 自测

1. `TEXT ·Add(SB), NOSPLIT, $0-24` 中每个部分的含义是什么？

TEXT定义函数类似于 func, ·ADD(SB)表示这是包级函数ADD 且·会被链接器转换成 go 中的 . , NOSPLIT 表示不开启栈分裂, $0-24中 0 是帧大小 24 是参数大小

2. 为什么汇编函数里读参数用 `0(FP)`、`8(FP)`，而不是寄存器？

FP是 go 语言汇编的虚拟寄存器, 存储栈帧指针, 参数由调用方传入, 通过 FP + 偏移地址读取参数, abi0 使用这种写法更稳定便于维护, 实际会转为 ABIINternal, 用的就是寄存器存取参数, 性能更好

3. `go vet` 对汇编函数检查了什么？

检查声明的函数函数是否存在, 以及参数大小是否计算正确

4. `main.Add.abi0` 符号和 Go 里的 `Add` 是什么关系？

这个就是 Add 的 abi0 声明吧? 我不太确定

### 验收批改结论（2026-10-19）

**工程验收：通过**

- `go tool objdump -s 'main\.Add' ./snake`：能看到 `main.Add.abi0` 和手写的 `MOVD`/`ADD`/`RET`。
- 变异测试：把 `ADD` 改成 `SUB` 后测试正确失败，证明断言有效。

**自测题批改**

1. ⚠️ 部分正确。`$0-24` 中 `0` 是本地帧大小，`24` 是**参数 + 返回值**的总大小：`a` 8 + `b` 8 + `ret` 8 = 24，不是只有参数。`·` 是包分隔符，汇编器把 `·Add` 变成符号 `main.Add`；`SB` 是静态基址伪寄存器，用来引用符号地址。注意题目里是 `Add`，大小写敏感。
2. ⚠️ 前半正确，后半需要修正。手写汇编是 ABI0，参数和返回值都在栈上，`FP` 是虚拟帧指针伪寄存器，汇编器把 `a+0(FP)` 解析成栈偏移。Go 调用方使用的是 ABIInternal（寄存器传参），编译器会生成 ABI 包装函数在两者之间转换；汇编函数本身**不会**被转换成 ABIInternal。
3. ✅ 基本正确。`go vet` 的 asmdecl 检查会用汇编里的 `$帧-参数`、FP 偏移和参数名，与 Go 声明逐项对照，可报告 `missing Go declaration`、`wrong argument size`、`invalid offset`、`unknown parameter name`。例如把 `$0-24` 写成 `$0-16`，`go build` 仍然成功，但 `go vet` 会报 `wrong argument size 16; expected $...-24`。
4. ❌ 需要补充。见下面的修正答案。

**修正后的第 4 题答案**

- `main.Add.abi0` 是 `add_arm64.s` 里手写的函数体，使用 ABI0 栈传参。
- Go 声明 `func Add(a, b int64) int64` 使用 ABIInternal（寄存器传参），编译器会生成一个 `<autogenerated>` 的 ABI 包装符号 `main.Add`：把 `R0`/`R1` 中的参数写到栈上，调用 `main.Add.abi0`，再把栈上的返回值搬回 `R0`。
- 当前程序里 `main` 是唯一调用者，包装函数被内联，所以 `go tool nm ./snake` 只看到 `main.Add.abi0`，`main.main` 直接 `CALL main.Add.abi0(SB)`。
- 如果把 `Add` 当函数值使用（`f := Add`），包装函数必须独立存在。此时 `go tool nm` 会同时显示 `main.Add` 和 `main.Add.abi0`，反汇编 `main.Add` 可以看到 `STP (R0, R1), 8(RSP)`、`CALL main.Add.abi0(SB)`、`MOVD 24(RSP), R0`，即完整的寄存器 ↔ 栈转换过程。

**结论：M0 通过，可以进入 M1。**
